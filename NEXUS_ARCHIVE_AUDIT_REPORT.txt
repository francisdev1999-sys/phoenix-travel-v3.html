  1. PROJECT OVERVIEW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  THE NEXUS ARCHIVE is an interactive, single-page web application for exploring
  conspiracy theories, ancient mysteries, alternative history, and unexplained
  phenomena. Content is presented as open theories and questions — not facts.

  The app lets users:
    - Browse 42 interconnected theory nodes in a force-directed knowledge graph
    - Explore 58 documented relationships between theories
    - Follow "rabbit holes" — algorithmically ranked multi-hop paths between ideas
    - Submit and review research sources with credibility scoring
    - Propose new nodes and edges (community contribution)
    - Earn XP and achievements for exploration
    - View theories on a 3D globe, timeline, and universe visualization

  Live URL:  phoenix-travel-v3html-production.up.railway.app
  Platform:  Railway (PostgreSQL + Node.js)
  Repo:      francisdev1999-sys/phoenix-travel-v3.html

  3. WHAT WE ACCOMPLISHED IN THIS SESSION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  This was a full production stabilization session — no features were added,
  only fires extinguished and foundations strengthened.

  [1] FIXED — P3018 Railway Deployment Crash (undefined_table "Source")
      The foundation migration was missing CREATE TABLE for Source, SourceLink,
      ProposedNode, and ProposedEdge. Added CREATE TABLE IF NOT EXISTS for all
      missing tables. Railway could now deploy successfully.

  [2] FIXED — Build Crash (PrismaClientInitializationError)
      Prisma 7.8 requires an adapter; calling new PrismaClient() without one
      at module load time (when DATABASE_URL is absent) crashed the Next.js
      build. Replaced direct construction with a Proxy pattern in lib/db.ts
      that defers the error to first DB access — never at build/import time.

  [3] FIXED — All 17 API Routes Missing force-dynamic
      Next.js tried to statically pre-render DB-touching routes at build time,
      causing eval errors. Added export const dynamic = 'force-dynamic' to all
      17 routes that touch the database.

  [4] ACCOMPLISHED — Full Database Seed (42 nodes, 58 edges, 216 sources)
      Could not run seed directly (sandbox network restrictions blocked Railway
      external URL). Created a temporary protected seed API endpoint on the
      live Railway app, triggered it remotely, then deleted it. Database is now
      fully populated.

  [5] FIXED — Auth Session Crash (page not loading)
      NextAuth crashed without AUTH_SECRET, with the PrismaAdapter when DB was
      a Proxy object, and with empty GitHub clientId. Fixed: added fallback
      secret, made adapter conditional on DATABASE_URL, made GitHub provider
      conditional on credentials being present.

  [6] FIXED — Page Blinking (auth polling loop)
      SessionProvider was polling /api/auth/session which kept erroring.
      Added refetchInterval={0} and refetchOnWindowFocus={false} to stop
      all polling and eliminate the re-render loop that caused visible blinking.

  [7] FIXED — Rabbit Hole "Page Not Found" on Node Selection (first time)
      DB returns camelCase fields (evidenceLevel) but the frontend expects
      snake_case (evidence_level). ConnectionCard and NodeHeader crashed on
      node.evidence_level.replace(). Added enrichResponse() to the rabbit hole
      API route that normalizes all node objects using the static node map as
      source of truth before sending to the client.

  [8] FIXED — Knowledge Graph Canvas Showing Nothing
      The canvas element used flex-1 in a flex container. HTML canvas is an
      inline replaced element with a 150px intrinsic height — align-items:
      stretch was not reliably overriding this. Switched the canvas to
      position: absolute; inset: 0; width: 100%; height: 100% so its
      dimensions always correctly match the container regardless of flexbox.

  [9] FIXED — Rabbit Hole Blink/Flash on Node Navigation
      setData(null) in the load() function cleared the view immediately on
      every navigation, causing a visible flash. Removed the immediate clear —
      old data now stays visible (dimmed at 60% opacity) while new data loads.
      A thin pulsing purple bar signals the in-flight request. Only clears on
      actual 404 errors.

  [10] FIXED — Page Blink on Every Page Reload
       Zustand persist was saving currentView to localStorage. Every reload
       rehydrated from 'landing' to the last active view (e.g. 'rabbit-hole'),
       triggering the motion.div fade-in animation — that was the "blink."
       Added partialize config to persist only: progress, audioEnabled,
       rabbitHoleChain, rabbitHoleNodeId. View state now always resets to
       landing on page load.

  [11] FIXED — AuthBoundary Infinite Re-render Loop
       The old AuthBoundary always rendered this.props.children even when
       failed: true — re-rendering the same crashing children on every error
       cycle. Fixed to render children WITHOUT SessionProvider as the fallback,
       breaking the loop. App works even if auth is completely broken.

  [12] FIXED — Rabbit Hole Spinner on Every Mount
       RabbitHoleView initialized currentId from the persisted rabbitHoleNodeId,
       causing it to immediately start loading the last-visited node (showing
       the "Computing intelligence paths" spinner) every time the page was
       opened. Changed to initialize as empty string — user always starts at
       the search/selection screen.

  [13] FIXED — Rabbit Hole "Node Not Found" for Valid Static Nodes
       Critical logic bug in the route handler: when computeRabbitHoleFromDB()
       returned null (node not in DB with status='published', or BFS found
       nothing), the route immediately returned 404 without ever trying the
       in-memory static-data fallback. The fallback only ran when the DB threw
       an exception, not when it returned null. Restructured the try/catch so
       null from DB also falls through to the static graph. All 42 static nodes
       now always resolve correctly regardless of DB state.

  [14] ADDED — Null Safety Guards on evidence_level
       Added (node.evidence_level ?? 'unknown').replace('_', ' ') to both
       NodeHeader and ConnectionCard to prevent TypeErrors if any node slips
       through without the field set, preventing app-level crashes.
