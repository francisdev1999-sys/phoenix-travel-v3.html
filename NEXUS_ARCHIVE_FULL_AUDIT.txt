================================================================================
 1. PROJECT OVERVIEW
================================================================================

Name:     THE NEXUS ARCHIVE
Purpose:  A community-driven, research-grade knowledge graph for exploring
          alternative history theories, ancient mysteries, archaeological
          anomalies, UAP research, mythology, and suppressed history.

Key Principles:
  - Every claim must trace back to a cited source
  - Trust is earned, not assumed
  - Content quality is enforced at every layer (gate → validate → review)
  - Ranks and badges are recognition only — they NEVER grant authority
  - The audit trail is immutable — no event is ever deleted

 5. API ROUTES (ALL 40+)
================================================================================

────────────────────────────────────────────────────────────────────────────────
 AUTHENTICATION
────────────────────────────────────────────────────────────────────────────────

GET  /api/auth/[...nextauth]    NextAuth session handler
POST /api/auth/[...nextauth]    OAuth callback handler

────────────────────────────────────────────────────────────────────────────────
 USER
────────────────────────────────────────────────────────────────────────────────

GET  /api/user/profile          Public or own profile
                                Own: auto-triggers evaluateBadges + refreshUserRank
                                Returns: trust, activity, rank, badges, counters

GET  /api/progress              Client-side user exploration progress

────────────────────────────────────────────────────────────────────────────────
 KNOWLEDGE GRAPH — NODES
────────────────────────────────────────────────────────────────────────────────

GET    /api/nodes/propose       List proposed nodes (paginated, status filter)
                                Non-admin: own + approved only
POST   /api/nodes/propose       Submit node proposal
                                Gates: trust ≥ 20, rate limit, content validation,
                                       duplicate detection (pg_trgm)
                                Returns: proposal + warnings + risk level
                                Side-effect: submissionCount++, logActivity

GET    /api/nodes/drafts        Admin draft queue with per-node quality scores

GET    /api/nodes/[id]          Single node: content, neighbours, sources,
                                research score, AI review (if exists)
PATCH  /api/nodes/[id]          Admin edit (increments version, creates NodeVersion)

POST   /api/nodes/[id]/review   Admin approve / reject / needs_revision
                                Approve: creates live Node from ProposedNode,
                                         creates NodeVersion v1, upserts Category,
                                         fires trust event +5 (approved_node),
                                         increments approvedCount,
                                         evaluateBadges + refreshUserRank
                                Reject: fires trust event -3 (rejected_content),
                                        increments rejectedCount,
                                        evaluateBadges + refreshUserRank

POST   /api/nodes/[id]/publish  Move draft → published
                                Enqueues: embed-node, rebuild-adjacency jobs
                                Triggers: suggestion engine run

GET    /api/nodes/[id]/source-quality   Source credibility assessment for node
GET    /api/nodes/[id]/sources          List sources linked to node
POST   /api/nodes/[id]/sources          Create source-node link
GET    /api/nodes/[id]/versions         Version history (admin only)

────────────────────────────────────────────────────────────────────────────────
 KNOWLEDGE GRAPH — EDGES
────────────────────────────────────────────────────────────────────────────────

GET  /api/edges/propose         List edge proposals (status filter)
POST /api/edges/propose         Submit edge proposal
                                Gates: trust ≥ 20, rate limit
                                Validation: self-loop guard, enum checks
                                Side-effect: submissionCount++, logActivity

POST /api/edges/[id]/review     Admin approve / reject / needs_revision
                                Approve: trust +2 (approved_relationship),
                                         approvedCount++, badges, rank
                                Reject: trust -3, rejectedCount++, badges, rank

────────────────────────────────────────────────────────────────────────────────
 SOURCES
────────────────────────────────────────────────────────────────────────────────

GET  /api/sources               List sources (page, status, type, q, mine filters)
                                Non-admin: approved + own only
POST /api/sources               Submit new source
                                Gates: trust ≥ 20, rate limit
                                Validation: sourceType enum check
                                Auto-computes credibility score on create
                                Side-effect: submissionCount++, logActivity

GET   /api/sources/[id]         Source detail
PATCH /api/sources/[id]         Admin edit source metadata

POST  /api/sources/[id]/review  Admin approve / reject / needs_revision
                                Approve: trust +3 (approved_source),
                                         approvedCount++, badges, rank,
                                         triggers source-quality re-compute
                                         on all linked nodes
                                Reject: trust -3, rejectedCount++, badges, rank

POST  /api/sources/[id]/override        Admin manually set credibility score
GET   /api/sources/[id]/links           Sources linked to specific targets
POST  /api/sources/duplicate-check      Duplicate detection before submission

 8.5 QUALITY GATES & RISK CLASSIFIER

  Daily limits per role:

  RED:    any HIGH_RISK keyword in title or description
  YELLOW: any MEDIUM_RISK keyword, OR evidenceLevel IN [speculative, mythological]

 8.9 COMMUNITY SUBMISSION WORKFLOWS
────────────────────────────────────────────────────────────────────────────────

All three submission types (ProposedNode, ProposedEdge, Source) follow the same

────────────────────────────────────────────────────────────────────────────────
 8.10 ADMIN REVIEW WORKFLOWS
────────────────────────────────────────────────────────────────────────────────

Three-stage lifecycle for nodes: pending → approved/rejected/needs_revision
  needs_revision → user can resubmit (they see the status + reviewNotes)

On Approve (ProposedNode):
  1. Derive nodeId slug from proposal.nodeId or label
  2. Guard: 409 if slug already exists as a live node
  3. Upsert Category (creates new category if needed)
  4. Transaction:
     a. Create Node (status: draft)
     b. Create NodeTags (many)
     c. Create Claims (many, with orderIndex)
     d. Create Criticisms (many, with orderIndex)
     e. Create OpenQuestions (many, with orderIndex)
     f. Create NodeVersion v1 (full snapshot)
     g. Update ProposedNode (status: approved, nodeId set)
  5. writeAuditLog(approve)
  6. Fire-and-forget on submitter:
     applyTrustEvent(+5, approved_node)
     approvedCount++
     evaluateBadges()
     refreshUserRank()
  7. Return: { proposal, node: { id, status: draft, title }, message }
  Note: Node enters as DRAFT — admin must explicitly publish to make it live.

On Reject:
  1. Update ProposedNode status: rejected + reviewNotes
  2. writeAuditLog(reject)
  3. Fire-and-forget on submitter:
     applyTrustEvent(-3, rejected_content)
     rejectedCount++
     evaluateBadges()
     refreshUserRank()

Source review follows the same pattern but also triggers source-quality recompute
on all linked nodes when approved.

Edge review applies trust events (+2 approve / -3 reject) on the edge submitter.
